## Phase Goal

**As a** contributor building the course domain, **I want to** run DCB on a pinned Axon Server locally and in CI with the JVM test infrastructure in place, **so that** every high-risk unknown is resolved and recorded before domain code is written.

<objective>
Create the events and commands contract modules and the shared Jackson module, ported from spike 002 with the
production changes from PATTERNS (D-44: `@JsonTypeInfo` on the sealed result instead of a mix-in), and prove the
Kotlin serialization round trip in a unit test (INFRA-06). Create the queries contract module as well, so all four D-02
modules (kernel, commands, events, queries) exist in Phase 2 and fall under the contracts architecture rules of plan
02-11 from the start; it holds no query message until the first query slice.

The messages are the first ones of the walking skeleton and exactly the shapes the spikes proved; their names and
versions become one-way only when Phase 3 persists the first event (D-03). Decision logic (handlers, invariants)
stays out of Phase 2.

Purpose: the command service (plan 02-07 onward) registers this mapper with Axon and uses these messages in the
permanent Axon Server tests.
Output: `:contracts-events`, `:contracts-commands`, `:contracts-queries`, `:serialization-jackson` and
`JsonRoundTripTest`.
</objective>
