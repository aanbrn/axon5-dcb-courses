## Phase Goal

**As a** contributor building the course domain, **I want to** run DCB on a pinned Axon Server locally and in CI with the JVM test infrastructure in place, **so that** every high-risk unknown is resolved and recorded before domain code is written.

<objective>
Check every JVM dependency licence in CI against an allowlist, with the Axoniq commercial-terms modules listed and
justified, and add a NOTICE file (CICD-09, D-30, D-31). The check reads a per-module CycloneDX SBOM, which Phase 6
reuses for image SBOMs.

Purpose: a forbidden or unknown licence can never enter the build unnoticed, and the Axoniq terms are explicit.
Output: `courses.licences`, `DependencyLicenceCheck`, `NoticeCheck`, the policy file, `NOTICE`, TestKit tests.

Requirement scope (CICD-09 says "JVM and npm"): this plan delivers the JVM half, which is everything Phase 2 can check,
because the repository has no npm project dependencies yet. D-30 decides that npm uses the same approach, and the npm
half is owned by Phase 5 (REQUIREMENTS.md traceability `CICD-09 | Phase 2 (JVM), Phase 5 (npm)`; ROADMAP Cross-Cutting
row `CICD-09 (npm half), UPS-02 (index on the site) | Phase 5`): it joins with the frontend's `package.json` and
`pnpm-lock.yaml`, reusing `governance/dependency-licences.json` and `NOTICE`. The policy file and the check are written
so that a second SBOM source plugs in without changing the rules. The two MCP servers that plan 02-02 pins as mise
`npm:` tools are developer tooling, not project dependencies: they are out of the CICD-09 check and reviewed through
the AIDEV-04 approval gate.

Governance: `checkDependencyLicences` is the first governance check registered per module rather than on the root
project. Plan 02-20, which depends on this plan, puts its convention plugin inside the governed boundary with its ask
rule, makes CI's `build` job name the task so a build where no module registers it fails, and adds the tooling-inventory
note. It is a separate plan so that each plan stays below the file-count limit, and it runs in wave 10 because
`.github/workflows/ci.yml` and `docs/tooling.md` are also edited by plans 02-14 and 02-18. Until then the convention
plugin is outside the boundary on the phase branch only (T-02-59).
</objective>
