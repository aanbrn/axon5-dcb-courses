**As a** contributor building the course domain, **I want to** run DCB on a pinned Axon Server locally and in CI with the JVM test infrastructure in place, **so that** every high-risk unknown is resolved and recorded before domain code is written.

<objective>

tools, the Docker engine (colima or Docker Desktop), Testcontainers connectivity, the pinned GSD installation, MCP
servers and the Platform token, explains every fix, and never changes anything.

1. `scripts/doctor.sh` (bash, SPDX line 2, `set -euo pipefail`, shellcheck and shfmt clean): options `--ci` and `--help`; resolves the repository root from its own location (overridable by `DOCTOR_ROOT` for tests) and `HOME`; one function per check calling a shared `report <ok|warn|fail|skip> <check> <detail> [fix]` that prints `<status>  <check>: <detail>` and an indented `fix: <command>` line; a summary line with the counts; exit 1 when any `fail`. Shell checks in this task: `mise` (present, version satisfying `min_version` in `mise.toml`); `tools` (every tool pinned in `mise.toml` installed and active per `mise ls --current --json`; fix `mise install`; this is mise's installation state, not the binary checks Gradle runs); `java` (a Java runtime that can start the Gradle wrapper: `JAVA_HOME/bin/java` or `java` resolvable with `command -v`; presence only; fix `mise install` locally or `setup-java` in CI); `docker` (engine reachable through `docker info`, naming the context from `docker context show` and recognising colima and Docker Desktop). The shell reads neither the Node nor the JDK version file and runs no version probe of Node, the JDK or the formatter binaries. The final check `gradle` runs `./gradlew doctor --continue --console=plain` and reports `ok  gradle: every JVM-side check passed` or `fail  gradle: ./gradlew doctor reported failures above` with the fix "read the failing task's message; it names its fix". It is skipped with a `warn` when the `java` check failed, or when `DOCTOR_SKIP_GRADLE=1`, which only the shell tests set. `--continue` makes Gradle run every independent check and report each failure.
2. `:tooling:doctor` (`settings.gradle.kts` include, `qodana.yaml` `tooling/doctor/build`): `tooling/doctor/build.gradle.kts` applies `courses.kotlin-library`, depends on `project(":tooling:test-support")`, and registers two tasks. `testcontainersProbe` is a `JavaExec` (group `help`, description "Checks Testcontainers connectivity through the Testcontainers library; changes nothing.", `mainClass` `io.github.aanbrn.courses.doctor.DoctorKt`, runtime classpath, `environment("TESTCONTAINERS_RYUK_CONTAINER_IMAGE", <catalog image-ryuk>)`). `doctor` is a lifecycle task (group `help`, description "Runs every JVM-side environment check: Node and formatter binaries, daemon JVM consistency and Testcontainers connectivity; changes nothing."). `doctor` declares `dependsOn("testcontainersProbe", ":verifyNodeVersion", ":verifyShfmt", ":verifyTaplo", ":checkDaemonJvm")`. Task paths are strings, and the Gradle isolated-projects guide allows a lifecycle task to depend on another project's task by path ("Declaring the dependency by path is allowed, because Gradle resolves the path itself"), so no other project's model is touched. `Doctor.kt`: calls `DockerClientFactory.instance().client()`, prints `ok  testcontainers: <docker host>, server <version>, ryuk <enabled|disabled>` or `fail  testcontainers: <reason>` with fixes for colima (`tc.host` or `docker.host` in `~/.testcontainers.properties`, or `DOCKER_HOST`; `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE`) and Docker Desktop, and exits non-zero on failure.
3. `scripts/test-doctor.sh` (auto-run by CI's "Run shell tests"): builds a temporary repository tree (`mise.toml`, a copy of `doctor.sh`) and a fake `HOME`, puts fake `mise`, `java` and `docker` first on `PATH`, sets `DOCTOR_SKIP_GRADLE=1`, and asserts four cases. A second identical run prints identical output and leaves the temporary tree's checksums unchanged.
