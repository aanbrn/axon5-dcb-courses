## Phase Goal

**As a** contributor building the course domain, **I want to** run DCB on a pinned Axon Server locally and in CI with the JVM test infrastructure in place, **so that** every high-risk unknown is resolved and recorded before domain code is written.

<objective>
Create the upstream-record system's enforcement (UPS-01, UPS-02, D-33, D-45): a shared front-matter parser, a cacheable
Gradle check that validates records and keeps workaround markers and records consistent in both directions, the
generated index, and the record and issue templates (GH-12).

Requirement scope (UPS-02 ends with "the index with statuses is generated for the documentation site"): this plan
generates the index in a site-ready Markdown form; publishing it on the documentation site is owned by Phase 5, whose
skeleton creates the site (REQUIREMENTS.md traceability `UPS-02 | Phase 2 (markers, check, index), Phase 5 (index on
the documentation site)`; ROADMAP Cross-Cutting row `CICD-09 (npm half), UPS-02 (index on the site) | Phase 5`). In
Phase 2 the index is a build report, regenerated by every `check`.

Purpose: every workaround in the code points to a documented upstream case with removal criteria, and closed cases
leave no stale workaround behind.
Output: `FrontMatter`, `UpstreamRecordCheck` (`checkUpstreamRecords`), TestKit tests, two templates.
</objective>
