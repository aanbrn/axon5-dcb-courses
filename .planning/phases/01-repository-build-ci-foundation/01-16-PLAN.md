## Phase Goal

**As a** contributor, **I want to** clone the repository, install pinned tools, and build and check the whole multi-project build with one command, **so that** every commit and pull request is automatically formatted, analysed, licence-checked and governed.

<objective>
Close review finding WR-04. The shell label gate and the Gradle ask-rule check must read
`governance/governed-paths.txt` identically, so that one file has exactly one meaning.

Gap reason (01-REVIEW.md WR-04): `AskRulesCheck` trims each line with Kotlin's Unicode `trim()`, and its functional
test deliberately accepts `"  .mcp.json  "`. `check-pr.sh::load_globs` only drops empty lines. A governed entry with
leading whitespace is therefore matched literally in CI and never matches a real path, while the Gradle check still
passes. Spotless trims only trailing whitespace in `*.txt`, so nothing catches it.

The rule chosen (one grammar, enforced in both, tested on both sides):
1. Split the file on LF only.
2. Strip leading and trailing space, tab and carriage return, and nothing else.
3. Ignore empty lines and lines starting with `#`.
4. Every remaining entry must be printable ASCII (0x20 to 0x7E), otherwise both fail closed, naming each offending
   line in ascending order.
5. A file without entries fails both.

Trimming keeps the forgiving behaviour the Gradle side already blessed. The printable-ASCII rule settles the encoding
question deterministically: bash (C locale) and Kotlin (UTF-16 chars) can only disagree outside ASCII, so anything
outside ASCII fails closed. Comment support lets plan 01-17 document the governed-path boundary inside the file.

Purpose: AIDEV-06 (the CI gate) and AIDEV-08 (the ask rules) are derived from one list with one meaning.
Output: the grammar in `load_globs` and in a new internal `GovernedPaths` parser used by `AskRulesCheck`, the same
case table in `test-check-pr.sh` and `GovernedPathsFormatFunctionalTest`, and the WR-04 disposition.

Scope: WR-04 only. WR-02 (deferred by the author) and IN-01..IN-05 are out of scope. The real
`governance/governed-paths.txt` is not edited here; plan 01-17 extends it and is the first to use comments.

Governed paths: this plan edits `scripts/governance/**`, so Claude Code asks the author before each such edit
(expected). The build-logic Kotlin files become governed only in plan 01-17, so they do not prompt yet. The phase pull
request carries `governance-approved`. No GitHub-side write happens in this plan.

Execution environment: run Gradle as `mise x -- ./gradlew ...` and tools as `mise x -- <tool>`. Keep every
`<automated>` command a single plain command (the harness refuses compound commands containing git or gh tokens).
Never run `git stash`. Never run `lefthook install`. `.planning/config.json` must not change. Run
`editorconfig-checker` separately. detekt is strict with no baseline (`TooManyFunctions` at 11 per class,
`ReturnCount` at 2, `MagicNumber`), and Dokka fails on warnings. Bash 3.2 rules apply (no associative arrays, no
expansion of a possibly empty array under `set -u`). Any file outside `.planning/**` that quotes SPDX tag text needs
`REUSE-IgnoreStart`/`REUSE-IgnoreEnd` fences; none is expected here.
</objective>
