## Phase Goal

**As a** contributor, **I want to** clone the repository, install pinned tools, and build and check the whole multi-project build with one command, **so that** every commit and pull request is automatically formatted, analysed, licence-checked and governed.

<objective>
Close UAT gap G-01-2 (major, UAT test 2). After this plan, a Node switch on `PATH` is seen by the build:
`verifyNodeVersion` checks, and Prettier runs with, the `node` first on the current build's `PATH`, also in a
warm Gradle daemon, and the configuration cache stays precise.

Root cause (binding, 01-UAT.md G-01-2 and `.planning/debug/node-binary-resolved-from-daemon-path.md`):
1. `VerifyNodeVersion` starts `node` by its bare name. The JDK resolves a name without `/` against `parentPathv`,
   a native copy of `PATH` cached once when the daemon JVM first initialises `ProcessImpl` (JDK-6413313). Gradle
   9.9.2 updates `System.getenv()` and the native environment for every build, so `System.getenv("PATH")` in a
   task action is current; only the bare-name lookup is stale. A warm daemon therefore runs the `node` of the
   client that started it.
2. Spotless Prettier (spotless-lib 4.11.0) never runs the verified node. With no explicit executable it searches
   for `npm` first and runs the `node` next to that `npm`. The guard (node first, stale) and the formatter (npm
   first, current) can pick different binaries, with or without a daemon.

Author direction (binding, verbatim in Russian in 01-UAT.md test 2): never rely on exec's own `PATH` lookup.
Resolve the absolute path yourself from `System.getenv("PATH")`, then exec that absolute path.

Purpose: the formatter that TEST-09 and D-05 rely on runs with the Node major `.nvmrc` pins (INFRA-09), as
verified, in every build. The configuration cache is invalidated exactly when a resolved binary changes (INFRA-10).
Output: the `ExecutableOnPath` value source; `VerifyNodeVersion` running the resolved path; Spotless Prettier
pointed at the same path; taplo and shfmt resolved by the same value source; and `ExecutableOnPathFunctionalTest`
with five TestKit tests.

Planner decisions (Claude's discretion; the UAT `missing` list is a non-binding example route):
- P-1: Spotless gets `nodeExecutable` only, not `npmExecutable`. spotless-lib 4.11.0 `NpmPathResolver.resolveNpmExecutable` already takes `<node dir>/npm` when it can execute it. `StandardNpmProcessFactory` starts npm with `PATH=<node dir>:$PATH`, so npm's `#!/usr/bin/env node` and the `node serve.js` start script both run the explicit node. Setting `npmExecutable(<node dir>/npm)` unconditionally would break a `PATH` whose node directory holds no npm, which is exactly the divergent case that test (b) pins.
- P-2: The shell-based lookup of taplo and shfmt in `courses.root` is replaced by the same value source (UAT "optional"). It is taken because that lookup launches the shell by bare name, which the author direction rules out, and because one resolution rule for every tool is simpler to reason about.
- P-3: The resolver skips relative `PATH` entries as well as empty ones. The planner verified the mechanism on Gradle 9.9.2 with a scratch daemon on 2026-11-22. Two builds ran in one daemon (PID 14499), one from a project directory that holds `relative-bin/node` and one from a directory that does not:
  - Gradle moves the daemon's native working directory to the build's directory for every build, and sets `user.dir` to it. So `File("relative-bin", "node").isFile` and `canExecute()` were true in the first build and false in the second, both at configuration time (inside a value source) and in a task action.
  - `File.absolutePath` still resolved against the directory the daemon JVM started in (`<gradle user home>/daemon/9.9.2/relative-bin/node`), because the JDK caches `user.dir` at startup.
  - A relative entry would therefore make the result depend on the directory each build was started from, and would yield an absolute path that does not exist. Skipping it keeps every result an existing absolute file and removes a binary-planting route through relative entries.
- P-4: `node-major.txt` keeps the major only (UAT "optional", not taken). UAT test 2 recorded major-only invalidation as by design. Observe and record in the SUMMARY whether Spotless's own step state now also re-runs Prettier on a node path change.
- P-5: The new tests go into a new class. `FormattingFunctionalTest` has 9 tests and the `GradleFixture` class body has 11 functions, against detekt's default `TooManyFunctions` limit of 11 per class (`allowedFunctionsPerClass: 11`, which the project config does not exclude for `functionalTest`). `GradleFixture` therefore gains a named `path` parameter, not new member functions.
- P-6: When shfmt is absent, the Spotless shell step keeps its existing fallback name. Spotless never runs it: `verifyShfmt` fails first, and because the value source is re-checked on every build, the fallback is only in effect while shfmt is absent.

Governed paths: this plan edits `build-logic/src/main/kotlin/courses.root.gradle.kts`, which `governance/governed-paths.txt`
lists. Claude Code's ask rules prompt the author before each such edit; that is expected, not a blocker. The phase
pull request carries `governance-approved`. `VerifyNodeVersion.kt`, the new `ExecutableOnPath.kt` (both in
`buildlogic/`, not `buildlogic/governance/`) and the functional tests are not governed. No governed-path entry
changes, and no GitHub-side write happens in this plan.

Out of scope: UAT tests 7 to 11 (blocked on the phase pull request) and the deferred GSD worktree-hook follow-up.

Execution environment (applies to every command here):
- Run Gradle as `mise x -- ./gradlew ...`; bare `./gradlew` fails `verifyTaplo` and `verifyShfmt` by design. Run tools as `mise x -- <tool>`.
- Commit with `mise x -- git commit -m "..."`. The author installed the lefthook pre-commit hook, so never pass `--no-verify`.
- Keep every `<automated>` command a single plain command. The harness refuses compound commands that contain git or gh tokens, and env-prefixed git.
- Never run `git stash`. Never run `lefthook install`; use only `lefthook run --no-auto-install`.
- `.planning/config.json` and `.nvmrc` must not change. Exercise other Node versions only through shim directories.
- `editorconfig-checker` is not part of `./gradlew check`, so run it separately.
- detekt is strict: KDoc on every public class, function and property (including nested interfaces and the test class itself), a first KDoc sentence ending with a period, no `@param` tags unless every parameter has one, and no KDoc links to non-public members. Dokka fails on warnings, so use backticks, not KDoc links, for JDK, Gradle and Spotless names.
- New Kotlin files start with the one-line SPDX header; `spotlessApply` adds it. No SPDX text is expected inside string literals.
- POSIX only (D-10: CI is ubuntu, local is macOS): shims are `#!/bin/sh` scripts, and Windows `PATHEXT` is not handled.
