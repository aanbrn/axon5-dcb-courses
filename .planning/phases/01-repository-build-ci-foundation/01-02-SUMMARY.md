## Decisions Made

- detekt now also analyses the `functionalTest` source set (the plugin default covers only `main` and `test`), so the TestKit code is held to the same bar. See deviation 1 for the exclusions this required.

- Fixtures run `:lib:build` and `:lib:*` tasks; running root `build` or `check` would reach `build-logic`'s `check` through the included build and recurse into `functionalTest`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] detekt naming and comments rules misfire on TestKit test classes**
- **Found during:** Task 2 (first full `./gradlew build` after adding the suite)
- **Issue:** The plan requires backticked prose test names, but detekt's `FunctionNaming` and the activated `comments` rules flagged every test method and `@TempDir` property, because detekt's built-in test exclusions match `**/test/**`, which does not match the `functionalTest` source set. `GradleFixture` also carried a stale `@property` tag for a private constructor parameter (`OutdatedDocumentation` wants `@param`, as noted in research Finding 4).
- **Fix:** `config/detekt/detekt.yml` sets `excludes` for `FunctionNaming`, `UndocumentedPublicFunction` and `UndocumentedPublicProperty` to detekt's own default test list plus `**/*FunctionalTest.kt`. These are path-scoped test exclusions that mirror detekt's defaults, not disabled rules, and `GradleFixture.kt` stays fully checked. The fixture KDoc tag became `@param`. No baseline, no rule deactivated.
- **Files modified:** `config/detekt/detekt.yml`, `GradleFixture.kt`
- **Verification:** `./gradlew build --rerun-tasks` green; the detekt TestKit test still fails on an undocumented public class in main code.
- **Committed in:** `bcf2c50`

**2. [Rule 1 - Bug] Fixture `build` would recurse into functionalTest**
- **Found during:** Task 2 (design, before writing the tests)
- **Issue:** The plan's behaviour says the fixture runs `build` twice. A fixture root `build`/`check` depends on `gradle.includedBuild("build-logic").task(":check")`, and the fixture includes the real build-logic, so it would run `functionalTest` inside `functionalTest`.
- **Fix:** Fixtures run `:lib:build` (and `:lib:*`, `spotlessCheck`, `spotlessApply` at the root). Cache reuse, invalidation and platform assertions are unchanged.
- **Files modified:** `ConventionsFunctionalTest.kt`
- **Verification:** all 8 tests pass; the second `:lib:build` prints `Reusing configuration cache.`
- **Committed in:** `bcf2c50`

**3. [Rule 1 - Bug] Dependency-report text differs from the plan's assumption**
- **Found during:** Task 2
- **Issue:** `dependencies --configuration implementation` is not resolvable in Gradle 9.9.2 and prints the declared entry as `project platform (n)` (without the colon), so a literal `project :platform` count read zero.
- **Fix:** the assertion counts the pattern `project :?platform`, exactly once per configuration; failure output now carries the report through `withClue`.
- **Files modified:** `ConventionsFunctionalTest.kt`
- **Verification:** both platform tests pass.
- **Committed in:** `bcf2c50`

**4. [Rule 3 - Blocking] Fixture needed the real `:platform`**
- **Found during:** Task 2
- **Issue:** with an empty `java-platform`, `:lib` failed to resolve `junit-jupiter` and `kotest-assertions-core` (no version).
- **Fix:** `GradleFixture.standard` copies the repository's `platform/build.gradle.kts`, added to the `repoFiles` task inputs.
- **Files modified:** `GradleFixture.kt`, `build-logic/build.gradle.kts`
- **Committed in:** `bcf2c50`
