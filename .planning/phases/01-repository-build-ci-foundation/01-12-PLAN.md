## Phase Goal

**As a** contributor, **I want to** clone the repository, install pinned tools, and build and check the whole multi-project build with one command, **so that** every commit and pull request is automatically formatted, analysed, licence-checked and governed.

<objective>
Every push and pull request is built, tested, analysed, linted and secret-scanned by hardened GitHub Actions
workflows that end in one stable `ci-success` context, plus CodeQL and OpenSSF Scorecard.

Purpose: CICD-01, CICD-03, CICD-06, CICD-08 and the CodeQL/Scorecard part of GH-06; this is the CI leg of the
walking skeleton.
Output: `ci.yml`, `codeql.yml`, `scorecard.yml`, two ADR-lite notes.

Phase 1 slice: CICD-01's "all test levels" are the sample `test` suite, the build-logic `functionalTest` suite
and the shell script tests. CICD-01's coverage clause is owned by Phase 3 (Kover, TEST-08) and CICD-08's
`docker compose config` validation by Phase 2 (first compose file); both are standing obligations with their
owning phase in the ROADMAP Cross-Cutting Conventions table. CICD-03 covers Actions here; base images are
Phase 6.

Hosted run: the first GitHub-hosted run of these workflows happens on the phase PR opened by `/gsd-ship`;
the ruleset applied in plan 01-14 blocks its merge until `ci-success` and `governance-success` are green.
This plan proves every job's commands locally and the workflows statically.

Execution environment (from plans 01-04 and 01-05 on): Spotless needs Node, shfmt and taplo from `mise.toml`/`.nvmrc`, so run
every Gradle command that formats or checks (`spotlessApply`, `spotlessCheck`, `check`, `build`, the formatting
TestKit tests) as `mise x -- ./gradlew …` unless mise is activated in the shell; this plan's commands assume it.

Context budget (recorded): estimate 70,000 tokens, 0.70 of the 100,000-token smart-zone budget — at the warning level, not over — with confidence low (calibration has no samples yet). Accepted for this plan; if the executor reports context pressure, Task 3 (CodeQL and Scorecard) moves to a follow-up plan, and the SUMMARY records the actual usage either way.
</objective>

| Boundary | Description |
|----------|-------------|
