## Phase Goal

**As a** contributor, **I want to** clone the repository, install pinned tools, and build and check the whole multi-project build with one command, **so that** every commit and pull request is automatically formatted, analysed, licence-checked and governed.

<objective>
Close review finding WR-01: the governed-path list must cover the code that enforces governance, so that a pull
request cannot switch a governance check off without the `governance-approved` label.

Gap reason (01-REVIEW.md WR-01): the list governs `governance/**`, `scripts/governance/**` and `.github/**`, but not
the Gradle half of the policy. A pull request can drop `checkGsdConfigPolicy` from `check` in
`courses.governance.gradle.kts`, or make `ConfigPolicyCheck` always pass, and stay green with no label.
`scripts/apply-github-settings.sh`, the only writer of the ruleset, is ungoverned too.

The boundary rule this plan writes into the file: a path is governed when a change to it alone can rewrite the policy,
stop a governance check from running, or make one pass without evaluating. That covers:
- the policy files;
- the checks and their wiring;
- the root build configuration that applies and selects them;
- the build that compiles them;
- the convention plugins applied to the root project and to settings;
- the launcher CI runs them with.

Beyond the reviewer's three paths, each added entry closes a concrete route:
- Root `build.gradle.kts` applies `courses.governance`, so deleting one line drops all six checks.
- Root `settings.gradle.kts` chooses the included build that supplies the plugin.
- A Groovy `build.gradle` or `settings.gradle` next to the Kotlin script is read first. This rests on the Gradle forum and is MEDIUM confidence, but governing a file that does not exist costs nothing.
- `buildSrc/**` would put plugins on every build script's classpath.
- `gradle.properties` holds the isolated-projects switch and the daemon JVM arguments.
- `courses.root` and `courses.settings` run in the root project's and the settings' configuration, where they can reconfigure the governance tasks by name.
- `gradlew`, `gradle/wrapper/**` and `gradle/gradle-daemon-jvm.properties` decide what runs `./gradlew build` in CI. A no-op `gradlew` alone would make the build step green.
- `docs/CODEOWNERS` is a CODEOWNERS location GitHub honours, and AIDEV-06 names CODEOWNERS.

Deliberately outside the list:
- Module convention plugins: under isolated projects they cannot reach the root project's tasks, and `checkBuildScripts` rejects `allprojects`, `subprojects` and `afterEvaluate`.
- Functional tests: a deleted test cannot make a check pass.
- The version catalog: dependency integrity is CICD-05 in Phase 6, and the catalog carries D-12 automerge updates.
- `gradlew.bat`: CI is ubuntu-only (D-10).
- `scripts/test-apply-github-settings.sh`: a test of the writer, not the writer.

The file states the accepted residual: build code can always subvert in-build checks by other means. The list makes
the direct routes visible changes, and the maintainer's review covers the rest. This is the same stance as T-01-20.

Purpose: AIDEV-06 (and the enforcement of AIDEV-05's config policy) cannot be switched off silently. AIDEV-08 keeps
the agent asking before it edits any of these paths.
Output: the extended, documented `governance/governed-paths.txt`, the matching ask rules, boundary tests and the
WR-01 disposition.

Scope: WR-01 only. WR-02 (deferred by the author) and IN-01..IN-05 are out of scope.

Governed paths and friction: this plan edits `governance/governed-paths.txt` and `.claude/settings.json`, which are
both governed, so Claude Code asks the author before each edit (expected). Once it lands, these edits need the label
and prompt the agent:
- every later edit of the newly governed files, for example adding a module to `settings.gradle.kts` in Phase 2;
- Renovate's Gradle wrapper pull requests, because the wrapper jar is not a version-only diff. Those are manual merges under D-12 already.

The phase pull request carries `governance-approved` anyway. No GitHub-side write happens in this plan.

Execution environment: run Gradle as `mise x -- ./gradlew ...` and tools as `mise x -- <tool>`. Keep every
`<automated>` command a single plain command (the harness refuses compound commands containing git or gh tokens).
Never run `git stash`. Never run `lefthook install`. `.planning/config.json` must not change. Run
`editorconfig-checker` separately.
</objective>
