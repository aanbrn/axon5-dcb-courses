## Phase Goal

**As a** contributor, **I want to** clone the repository, install pinned tools, and build and check the whole multi-project build with one command, **so that** every commit and pull request is automatically formatted, analysed, licence-checked and governed.

<objective>
`./gradlew check` enforces the repository's governance rules: the GSD config policy (AIDEV-05, D-14), no
version literals and no eager or cross-project build APIs (INFRA-09, INFRA-10), and `.java-version` and
daemon-JVM consistency (INFRA-09). The tooling-inventory check (TOOL-01, D-17) and the PR-template check
reuse the `courses.governance` plugin in plan 01-09.

Purpose: D-13 — governance checks are build-logic code with tests, not ad hoc scripts; CI enforces them
through the same `check`.
Output: `courses.governance` plugin, three `@CacheableTask` classes, the policy file, three TestKit test classes.

Phase 1 slice: INFRA-09's image references and npm versions get their checks in Phases 2, 5 and 6, recorded as
standing obligations with their owning phases in the ROADMAP Cross-Cutting Conventions table;
`checkBuildScripts` already scans every `*.gradle.kts` those phases add. The repository-wide `spotlessApply`
runs in this plan only format this plan's new files (the tree is already formatted by plan 01-04); if one
changes a file another plan owns, stop and report instead of committing it.

Execution environment (from plan 01-04 on): Spotless needs Node, shfmt and taplo from `mise.toml`/`.nvmrc`, so run
every Gradle command that formats or checks (`spotlessApply`, `spotlessCheck`, `check`, `build`, the formatting
TestKit tests) as `mise x -- ./gradlew …` unless mise is activated in the shell; this plan's commands assume it.
</objective>
