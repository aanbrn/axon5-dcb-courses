## Phase Goal

**As a** contributor, **I want to** clone the repository, install pinned tools, and build and check the whole multi-project build with one command, **so that** every commit and pull request is automatically formatted, analysed, licence-checked and governed.

<objective>
One command (`./gradlew spotlessApply`) formats every artifact type in the repository — not only Kotlin — and
`.editorconfig` agrees with every formatter, so CI and the hook can enforce formatting everywhere.

Purpose: completes TEST-09's formatting surface beyond Kotlin (D-05) and the project constraint that every
produced artifact is auto-formatted and style-checked; gives the hook and CI their editorconfig check (INFRA-14).
Output: Prettier, TOML, shell and generic-text formats in `courses.root`, `VerifyNodeVersion` task,
`.prettierrc.yaml`, `.taplo.toml`, `.editorconfig`, `.editorconfig-checker.json`, `FormattingFunctionalTest`.

Formatting side effects: the repository-wide `spotlessApply` reformats files earlier plans created
(`docs/tooling.md`, `config/detekt/detekt.yml`, `mise.toml`, `gradle/libs.versions.toml`; listed in
`files_modified` as reformat-only). Earlier plans wrote their other files whitespace-clean; if any other file
changes, commit it with the task and list it in the SUMMARY.

Phase 1 slice: TEST-09's TS/TSX formatting arrives with Biome in Phase 5. Line endings (`.gitattributes`) and
REUSE compliance are plan 01-05.

Execution environment (from plan 01-04 on): Spotless needs Node, shfmt and taplo from `mise.toml`/`.nvmrc`, so run
every Gradle command that formats or checks (`spotlessApply`, `spotlessCheck`, `check`, `build`, the formatting
TestKit tests) as `mise x -- ./gradlew …` unless mise is activated in the shell; this plan's commands assume it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → build | Spotless downloads Prettier from npm at build time |
| Developer or CI `PATH` → build | The build executes the taplo and shfmt binaries it finds on `PATH` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Tampering | Prettier fetched by Spotless | medium | mitigate | Version pinned in the catalog (Renovate-annotated, 7-day cooldown), legitimacy confirmed in plan 01-03, Node major verified by `verifyNodeVersion` (Task 1); no Prettier plugins, so no unpinned transitive npm dependencies |
| T-01-39 | Tampering | taplo and shfmt binaries executed by the build | medium | mitigate | Both pinned in `mise.toml` with per-platform checksums in `mise.lock` (plan 01-03) and installed by mise locally and in CI (plan 01-11); the resolved tool version is an input of the Spotless tasks (Task 3), so a different binary on `PATH` invalidates cached results instead of hiding behind them |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | Prettier (npm) was cleared by the blocking legitimacy checkpoint in plan 01-03; shfmt and taplo are GitHub-release binaries installed through mise, not npm/pip/cargo; no new packages here |
</threat_model>
