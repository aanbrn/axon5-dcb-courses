## Phase Goal

**As a** contributor, **I want to** clone the repository, install pinned tools, and build and check the whole multi-project build with one command, **so that** every commit and pull request is automatically formatted, analysed, licence-checked and governed.

<objective>
Fix review finding WR-05 (author decision for this gap-closure run: fix, not document). The `governance-approved`
gate must fail closed when it cannot read the complete changed-file list.

Gap reason (01-REVIEW.md WR-05, reproduced in 01-VERIFICATION.md): `check_governed_files` in
`scripts/governance/check-pr.sh` reads its per-file records from a `jq --raw-output0` process substitution. The shell
never sees that process's exit status and `set -e` does not either. When jq aborts part-way, `read` hits end of
input, the loop ends, every entry from the failing one onward is skipped, `touched` stays empty, and the gate prints
"no governed file is touched" and exits 0. Reproduced with a NUL in the patch of a governed second entry. It is the
same fail-open shape as CR-01, so the plan 01-15 prohibition ("any failure to interpret the list fails the check")
does not yet hold.

The fix the author chose has three parts, delivered in this order:
1. Write jq's records to a temporary file.
2. Check jq's exit status before the loop.
3. Assert that the loop saw exactly as many entries as the list holds.

The first two parts are the tracer (Task 1). The third part, and the matrix that proves each guard on its own, are
Task 2. NUL strings are deliberately not rejected up front in `validate_inputs`: that would make the reproduction
pass through input filtering and leave the status and count guards untested.

Purpose: Success Criterion 5 and AIDEV-06 hold for every list the gate receives. The gate either evaluates every
entry or fails.
Output: the hardened reading in `check-pr.sh`, cases R1 to R11 in `test-check-pr.sh`, and the WR-05 disposition.

Scope: WR-05 only. WR-07 is plan 01-19 and WR-06 is plan 01-20. WR-02 stays deferred, and IN-01 to IN-06 are out of
scope; this plan touches none of them.

Governed paths: this plan edits `scripts/governance/**`, which is governed. Claude Code's ask rules prompt the author
before each such edit; that is expected, not a blocker. The phase pull request carries `governance-approved`. No
GitHub-side write happens in this plan.

Execution environment (applies to every command here):
- Run Gradle as `mise x -- ./gradlew ...`; bare `./gradlew` fails `verifyTaplo` and `verifyShfmt` by design. Run tools as `mise x -- <tool>`.
- Commit with `mise x -- git commit -m "..."`. The author installed the lefthook pre-commit hook, so never pass `--no-verify`.
- Keep every `<automated>` command a single plain command. The harness refuses compound commands that contain git or gh tokens, and env-prefixed git.
- Never run `git stash`. Never run `lefthook install`; use only `lefthook run --no-auto-install`.
- `.planning/config.json` must not change.
- `editorconfig-checker` is not part of `./gradlew check`, so run it separately.
- detekt is strict.
- SPDX text outside `.planning/**` needs `REUSE-IgnoreStart`/`REUSE-IgnoreEnd` fences; none is expected here.
- Bash 3.2 compatibility (macOS `/bin/bash`, which is the `bash` on PATH here): no associative arrays, and no expansion of a possibly empty array under `set -u`.
