## Phase Goal

**As a** contributor, **I want to** clone the repository, install pinned tools, and build and check the whole multi-project build with one command, **so that** every commit and pull request is automatically formatted, analysed, licence-checked and governed.

<objective>
Every pull request that touches governance files needs the maintainer's `governance-approved` label to pass
`governance-success`, except narrowly defined Renovate version bumps; same-repository PRs must use the GSD or
bot branch naming.

Purpose: AIDEV-06 and the PR-context half of D-13; the D-16 exemption that makes D-12 automerge possible;
the head-branch part of GH-07 (rulesets on `main` cannot constrain head branch names).
Output: `governance/governed-paths.txt`, `scripts/governance/check-pr.sh` with tests, `.github/workflows/governance.yml`.

The label itself is created before the first PR in plan 01-13 (Pitfall 11 bootstrap); the ruleset makes
`governance-success` a required context in plans 01-12/01-13.

Execution environment (from plan 01-04 on): Spotless needs Node, shfmt and taplo from `mise.toml`/`.nvmrc`, so run
every Gradle command that formats or checks (`spotlessApply`, `spotlessCheck`, `check`, `build`, the formatting
TestKit tests) as `mise x -- ./gradlew …` unless mise is activated in the shell; this plan's commands assume it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author → CI | PR titles, branch names, labels and file lists are attacker-controlled input to the workflow |
| PR → `main` | Governance changes must be consciously approved by the maintainer |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-17 | Elevation of Privilege | Privileged PR trigger running PR code | high | mitigate | Only the `pull_request` event with a read-only token and no secrets; acceptance gate on the trigger (Task 1) |
| T-01-18 | Tampering | Script injection through PR title, branch or label values | high | mitigate | Every PR value passed via `env:`, no `${{ }}` in `run:`, JSON read only with `jq`, no `eval` (Tasks 1-2); zizmor template-injection audit |
| T-01-19 | Spoofing | Someone imitating the Renovate bot to use the exemption | medium | mitigate | Exact author `renovate[bot]` (the `[bot]` suffix is reserved for GitHub Apps) AND a version-only diff for every governed file (Task 2) |
| T-01-20 | Tampering | A PR edits the governance workflow or script so its own check passes | medium | mitigate | `.github/**` and `scripts/governance/**` are governed, so such a PR needs the label; the maintainer reviews the squash-merge diff; the agent is stopped by ask rules (plan 01-12). Residual risk (a malicious PR neutralising the check that runs from its own tree) is accepted at ASVS L1 because the only robust alternative runs PR-adjacent logic in a privileged context |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages; `jq` and `gh` come from the runner image in CI and from `mise.toml` locally, cleared in plan 01-03 |
</threat_model>
