## Phase Goal

**As a** contributor, **I want to** clone the repository, install pinned tools, and build and check the whole multi-project build with one command, **so that** every commit and pull request is automatically formatted, analysed, licence-checked and governed.

<objective>
GitHub repository settings and the `main` ruleset exist as reviewed code with an idempotent apply script and
a read-only drift check, and the agent must ask before it edits any governance file or runs GSD `config-set`.

Purpose: D-15 (settings as code, applied only after approval — the application itself is plan 01-11), GH-06,
GH-07 and AIDEV-08.
Output: ruleset and settings JSON, apply script with tests, drift workflow, `.claude/settings.json`, `AskRulesCheck`.

Ordering rule: Task 3 writes `.claude/settings.json` last. After it lands, every edit of a governed path
(including `.github/**`) prompts the author, so no governed file may be edited by an executor after this
task in Phase 1. GSD workflows that call `config-set` will prompt too; that is intended (RESEARCH Finding 8).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local admin `gh` session → GitHub settings | The apply script can change branch protection and security features |
| Agent → governance files | Claude Code can edit any file unless asked to confirm |
| Status reporters → required checks | Any GitHub App could post a status with the same context name |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-31 | Elevation of Privilege | Accidental settings change by the script | high | mitigate | Default mode `--dry-run`, writes only with `--apply`, tests prove no non-GET calls in dry-run and check modes (Task 1); application only after the blocking approval in plan 01-11 |
| T-01-32 | Spoofing | Another app posting a fake `ci-success` status | medium | mitigate | Required contexts bound to the GitHub Actions app via `integration_id` (Task 1) |
| T-01-33 | Information Disclosure | Drift-check token exposure | medium | mitigate | Read-only fine-grained token stored as a secret, referenced only in `env:`, never printed; workflow cannot run `--apply` (Task 2 gate) |
| T-01-34 | Tampering | Agent silently editing governance files or running `config-set` | high | mitigate | `permissions.ask` rules for every governed path and `config-set` (Task 3), kept in sync by `checkClaudeAskRules`; ask rules are not a security boundary, so CI (`checkGsdConfigPolicy`, `governance.yml`) remains the enforcement |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages; `gh` and `jq` from `mise.toml`, cleared by the legitimacy gate in plan 01-02 |
</threat_model>
