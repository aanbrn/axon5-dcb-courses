## Phase Goal

**As a** contributor, **I want to** clone the repository, install pinned tools, and build and check the whole multi-project build with one command, **so that** every commit and pull request is automatically formatted, analysed, licence-checked and governed.

<objective>
Tracer slice of the walking skeleton: a fresh clone builds and tests the sample module end to end through
the `build-logic` conventions, the `:platform` module and the version catalog, with configuration cache and
isolated projects on; then `:platform` grows into the single alignment point for every BOM INFRA-11 names.

Purpose: every later plan (quality gates, formatting, governance checks, CI) plugs into this build. Proving
the architecture first (D-02, D-04, D-19) means a dead end costs one commit, not ten.
Output: Gradle wrapper, settings, catalog, `courses.settings` and `courses.kotlin-library`, `:platform` with all
stack BOMs, `:tooling:convention-sample` (D-22), `.java-version`, `gradle.properties`, a comprehensive `.gitignore`.

Accepted scope deviation (file count): 17 `files_modified` entries exceed the 10-file warning threshold, and the
excess is accepted for this plan. The four wrapper files are generated by `gradle wrapper`; of the 13 hand-written
files, eight are one to ten lines (`.java-version`, `gradle.properties`, `.gitignore` additions, both settings
files, `courses.settings`, `platform/build.gradle.kts`, the sample build file). Every file is one layer of the
single end-to-end path, so the slice cannot be split further without losing the tracer (the `.gitignore` lines
for build output must land with the first build). The context estimate stays at 0.50 of the budget. The SUMMARY
repeats this acceptance. Quality gates and the TestKit suite are plan 01-02.

Recorded deferral (not a Phase 1 requirement): Gradle dependency locking and `gradle/verification-metadata.xml`
from the CLAUDE.md stack table are left to the phase that first needs exact resolved versions for scanning
(Phase 6, CICD-05); `.gitattributes` (plan 01-06) already marks the verification file as generated. The SUMMARY
lists this deferral for the author.

Phase 1 slice of whole-project requirements: INFRA-09 here covers the catalog and `.java-version` (the
generated daemon-JVM file is plan 01-02, the literal check plan 01-07). INFRA-10 here covers configuration
cache, build cache, parallel execution, isolated projects and JVM args (daemon JVM criteria are plan 01-02,
CI caching plan 01-12, gradle-profiler plan 01-08). The sub-scopes of INFRA-09 and INFRA-10 that need later
artefacts — container image pins with digests (Phases 2 and 6), `packageManager`, exact npm versions and the
Gradle Node plugin reading `.nvmrc` (Phase 5), Testcontainers singletons (Phase 2) and reused buildpack caches
(Phase 6) — are standing obligations with their owning phases in the ROADMAP Cross-Cutting Conventions table.
