Decisions taken in this plan (planner, from the task description):
- WR-01, unknown version: a server version whose part before the first `-` or `+` is not `MAJOR.MINOR.PATCH` (for
  example `dev`) gives a `warn` with the same fix lines, because doctor cannot show that the engine meets the minimum.
  It is a warn and not a fail, like the older-engine case: the defect hits only image builds, which no local check
  needs. The suffix is dropped before comparing, so `29.10.0+azure-1` (the Microsoft moby package of GitHub runners)
  compares as 29.10.0 and a pre-release `29.9.0-rc.1` as 29.9.0. check_docker only sets DOCKER_OK with a non-empty
  version, so an empty version never reaches the check.
- WR-01, classic store: the ok line now names the server version too, so both branches read alike.
- IN-01, severity: the task description says these servers "report fail", and this plan uses doctor's `fail` status.
  Rationale: a server entry with neither a command nor a url can never start; that is a defect of the committed
  `.mcp.json`, while an unresolved binary of a well-formed server stays a `warn` that `mise install` fixes. The review
  suggested listing such a server among the unresolved binaries (a warn); the description's explicit `fail` wins. An
  unreadable `.mcp.json` stays a warn (out of scope). The orchestrator surfaces this choice to the author (see notes).
- IN-01, url: "a string url" means a non-empty string, through the existing jq `text` helper, as the review's fix does
  and as `command` is already treated; an empty url can be connected to no more than an empty command can be run.
